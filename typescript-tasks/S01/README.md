# Семинар: базовые типы TypeScript

Стартовый репозиторий к лекции «Базовые типы TypeScript».
Проверка типов включена в строгом режиме (`strict`, `noUncheckedIndexedAccess`).

## Установка

```bash
npm install
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run check` | Проверка типов по всему проекту (кроме разминки) |
| `npm run warmup` | Проверка типов только для задания 0 |
| `npm test` | Прогон всех тестов |
| `npm run test:watch` | Тесты в режиме наблюдения |

## Правила

1. Нельзя использовать `any`, `as`, `!` и `@ts-ignore`. Если хочется их
   написать — задание решается не так.
2. Задание сдано, когда `npm run check` не выдаёт ошибок,
   а `npm test` зелёный.
3. Часть тестов проверяет обратное: строка, помеченная `@ts-expect-error`,
   обязана **не** компилироваться. Если вы ослабите типы, такой тест
   сломается на этапе проверки типов — это тоже провал.

## Задания

| Файл | Задание | Время |
|---|---|---|
| `src/00-warmup.ts` | Разминка: почини типы | 10 мин |
| `src/01-status.ts` | Статусы: литеральные типы и `assertNever` | 15 мин |
| `src/02-user.ts` | Карточка пользователя: опциональные поля и `in` | 15 мин |
| `src/03-payment.ts` | Платежи: размеченное объединение | 20 мин |
| `src/04-validation.ts` | Правила валидации через `keyof` | со звёздочкой |

Разминка вынесена из основной проверки: в `src/00-warmup.ts` семь ошибок
по одной на пронумерованный пример, и `npm run check` их не видит.
Проверяйте её отдельно командой `npm run warmup` — цель в том, чтобы
вывод стал пустым.

В заданиях 1 и 3 после того, как всё заработает, добавьте новый вариант
в объединение (`"cancelled"` и четвёртый способ оплаты) и посмотрите,
где компилятор покажет незакрытые места. Это и есть главный приём лекции.
